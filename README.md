# MangaPlus — موقع المانجا والروايات العربية

موقع عربي كامل (RTL) لمنصة **MangaPlus**، مبني بـ React وVite، ويعمل كواجهة ويب مكمّلة لتطبيق MangaPlus على أندرويد. يشمل الموقع كتالوج أعمال، صفحات تفاصيل، قارئ مانجا وقارئ روايات، مكتبة محلية، وحساباً مشتركاً مع التطبيق عبر Firebase Authentication.

> **ملاحظة عن المحتوى:** الأعمال والفصول والنصوص في هذا المستودع **بيانات تجريبية** صُممت لاختبار الواجهة. الأغلفة وصفحات المانجا تُولَّد برمجياً (SVG) ولا تستخدم أعمالاً محمية بحقوق نشر.

## المزايا

- **واجهة عربية RTL كاملة** مع خطوط IBM Plex Sans Arabic وAmiri مستضافة محلياً (لا طلبات لخطوط خارجية).
- **وضع فاتح وداكن** يُحفظ محلياً ويُطبَّق قبل الرسم الأول لتجنب الوميض.
- **14 عملاً تجريبياً** (9 مانجا و5 روايات) مع بحث وتصنيفات وحالات وترتيب.
- **قارئ مانجا** بوضعين: تمرير عمودي أو صفحات، مع ملء الشاشة، تقدّم تلقائي، واستعادة آخر صفحة.
- **قارئ روايات** بتحكم في حجم الخط وارتفاع السطر ونوع الخط ولون الخلفية، وفهرس فصول.
- **مكتبة على الجهاز**: المفضلة، المتابعة، سجل القراءة، وإكمال القراءة من حيث توقفت.
- **حساب Firebase واحد** للموقع والتطبيق: تسجيل الدخول، إنشاء حساب، التحقق من البريد، واستعادة كلمة المرور عبر صفحة `/auth-action` مخصصة.
- **حالات واضحة** للتحميل (Skeleton)، والفراغ، والأخطاء، وعدم تهيئة Firebase — دون رسائل تقنية للمستخدم.
- **SEO أساسي**: عناوين وأوصاف لكل صفحة، Open Graph، `sitemap.xml` و`robots.txt` يُولَّدان عند البناء عند ضبط `SITE_URL`.

## التقنيات

- **React 19** + **TypeScript** + **Vite 7**
- **React Router 7** (توجيه من جهة العميل مع صفحات lazy)
- **Firebase 11** (Authentication فقط، ويُحمَّل ديناميكياً)
- **CSS مخصص** بنظام Tokens (بدون Tailwind أو مكتبة UI)
- لا Backend ولا قاعدة بيانات في هذا المستودع.

## التشغيل المحلي

يتطلب Node.js 20+.

```bash
npm ci
npm run dev
```

يعمل الخادم على `http://localhost:5173` افتراضياً. لتغيير المنفذ:

```bash
npm run dev -- --port 3000
```

> إذا كنت تعرض الخادم عبر نفق/معاينة خارجية، مرّر اسم المضيف في `PREVIEW_HOST` (يُقرأ في `vite.config.ts` ويُضاف إلى `server.allowedHosts`).

### متغيرات البيئة

انسخ `.env.example` إلى `.env.local` واملأ القيم:

```env
VITE_FIREBASE_API_KEY=
VITE_FIREBASE_AUTH_DOMAIN=
VITE_FIREBASE_PROJECT_ID=
VITE_FIREBASE_STORAGE_BUCKET=
VITE_FIREBASE_MESSAGING_SENDER_ID=
VITE_FIREBASE_APP_ID=
VITE_SITE_URL=
```

هذه **معرّفات عميل عامة** وليست أسراراً، لكنها تبقى خارج Git. لا تضع أي مفتاح خدمة (Service Account) في مشروع الواجهة.

## إعداد Firebase

يستخدم الموقع **مشروع Firebase نفسه** الخاص بالتطبيق، دون إنشاء مشروع جديد ودون قاعدة بيانات.

1. من Firebase Console → **Project settings → Your apps** اختر تطبيق الويب أو أنشئ واحداً، ثم انسخ قيم `firebaseConfig` إلى متغيرات `VITE_FIREBASE_*`.
2. في **Authentication → Sign-in method** فعّل **Email/Password**.
3. في **Authentication → Settings → Authorized domains** تأكد من وجود `looooooooord.github.io` (النطاق فقط، بلا مسار ولا `www`)، ومن وجود `localhost` للتطوير. بدونه ترفض Firebase روابط البريد التي تعود إلى الموقع وتظهر رسالة تعذّر.
4. في **Authentication → Templates** افتح قالب **Email address verification** وقالب **Password reset**، ثم اضبط **Customize action URL** على:
   ```text
   https://looooooooord.github.io/Mangaplus-website/auth-action
   ```
   هذا يجعل روابط البريد تفتح صفحة الموقع المخصصة بدل الصفحة الافتراضية.
5. أعد تشغيل خادم التطوير بعد تعديل `.env.local`.

> بدون هذه القيم تعمل بقية الصفحات بشكل طبيعي، وتظهر صفحات الحساب والمصادقة حالة **«تسجيل الدخول غير متاح حالياً»** بدل تعطّل الموقع.

### كيف يعمل تدفق الحساب

- `src/firebase/client.ts` يحمّل Firebase ديناميكياً فقط عند اكتمال الإعداد.
- `src/services/auth.ts` يغلّف إنشاء الحساب، الدخول، التحقق من البريد، وإعادة التعيين.
- `src/pages/AuthAction.tsx` يقرأ `mode` و`oobCode` من رابط Firebase، ينفّذ العملية، ثم يخفي الرمز من شريط العنوان.
- أخطاء Firebase تُترجم في `src/firebase/errors.ts` إلى رسائل عربية واضحة دون تفاصيل تقنية.

## المكتبة المحلية والتكامل مع التطبيق

حالياً تُحفظ المفضلة والمتابعة وسجل القراءة في `localStorage` على جهاز الزائر، وتُعرض في الواجهة بعبارة **«محفوظة على هذا الجهاز»** — لا توجد مزامنة سحابية ولا ادعاء بوجودها.

لتفعيل المزامنة لاحقاً مع حساب التطبيق، وُضع عقد تكامل في `src/services/accountLibrary.ts`:

```ts
registerAccountLibraryProvider({
  setFavorite(workId, value) { /* ... */ },
  setFollow(workId, value) { /* ... */ },
  saveProgress(entry) { /* ... */ },
});
```

عند تسجيل مزوّد، تستدعيه `LibraryContext` تلقائياً بعد كل تغيير محلي. لا يوجد في هذا المستودع Backend يوفّر هذا المزوّد.

## البناء والنشر

```bash
SITE_URL="https://mangaplus.example" npm run build
```

- يبني `dist/` ويولّد:
  - `sitemap.xml` لكل الصفحات العامة والأعمال.
  - `robots.txt` مع استثناء صفحات الحساب والقارئ والبحث.
  - `404.html` (نسخة من `index.html`) لاستمرار الروابط العميقة.
  - روابط Open Graph مطلقة (`og:image`, `og:url`).
- بدون `SITE_URL` يكتمل البناء لكن تُتخطى خريطة الموقع وتبقى روابط OG نسبية.

### الاستضافة

الموقع تطبيق صفحة واحدة (SPA)، ويحتاج إعادة كتابة كل المسارات إلى `index.html`:

- **GitHub Pages (مُفعّل)**: ينشر `.github/workflows/deploy-pages.yml` الموقع تلقائياً عند كل دفعة إلى `main`، على المسار <https://looooooooord.github.io/Mangaplus-website/>. يبني الـworkflow الموقع بـ`BASE_PATH=/Mangaplus-website/` و`VITE_SITE_URL`، ثم يدفع ناتج `dist/` إلى فرع `gh-pages`، وهو مصدر النشر الحالي في إعدادات المستودع (**Deploy from a branch → gh-pages → /root**). قيم Firebase الستة تُقرأ من **Settings → Secrets and variables → Actions** بأسماء `VITE_FIREBASE_*`؛ بدونها يُبنى الموقع لكن تظهر صفحات الحساب بحالة «غير متاح حالياً».
- **Netlify / Cloudflare Pages**: `public/_redirects` الموجود يغطي إعادة التوجيه (`/* /index.html 200`).
- **Vercel**: أضف Rewrite إلى `/index.html` للمسارات غير الموجودة.

للنشر على مسار فرعي يدوياً:

```bash
BASE_PATH=/Mangaplus-website/ VITE_SITE_URL=https://looooooooord.github.io/Mangaplus-website npm run build
```

يقبل `postbuild` المتغير `SITE_URL` أو `VITE_SITE_URL`، لكن كود الواجهة يقرأ `VITE_SITE_URL` فقط لأنه يبني منه رابط `/auth-action` الذي يُرسل إلى Firebase.

يمكنك معاينة الإنتاج محلياً (مرّر `BASE_PATH` نفسه إن بنيت لمسار فرعي):

```bash
BASE_PATH=/Mangaplus-website/ npm run preview
```

## الاختبارات والتحقق

لا توجد مجموعة اختبارات آلية بعد. التحقق المتّبع في هذا المستودع:

```bash
npx tsc --noEmit
npm run build
```

تم فحص الواجهة بصرياً على عرض 390 و768 و1440 بكسل، في الوضعين الفاتح والداكن، وتجربة: البحث والفلاتر، تفاصيل العمل، المفضلة والمتابعة، أوضاع القارئ وإعداداته، التنقل بين الفصول، حفظ التقدّم، صفحات المصادقة (حالة عدم التهيئة)، صفحة 404، ونافذة تأكيد مسح المكتبة.

**تم التحقق من اتصال المصادقة الحقيقي** بعد ربط المشروع بمشروع Firebase الخاص بالتطبيق: يظهر خطأ «البريد الإلكتروني أو كلمة المرور غير صحيحة» لبيانات دخول غير موجودة، وتُعالج روابط `/auth-action` غير الصالحة على المسار الفرعي. **لم يُختبر** إنشاء حساب فعلي ولا وصول رسالة التحقق أو إعادة التعيين إلى صندوق بريد، لأن ذلك يحتاج صندوق بريد اختبار.

## قيود معروفة

- **لا مزامنة بين الأجهزة**: المكتبة محلية حتى يتم توصيل مزوّد الحساب.
- **المصادقة معطّلة** حتى تُضاف قيم Firebase وتُضاف نطاقات الموقع إلى Authorized domains.
- **لا تحميل فعلي للتطبيق**: صفحة `/download` توضّح أن رابط التحميل لم يُنشر بعد، ولا تعرض رابطاً وهمياً.
- **بيانات تجريبية**: الأعمال والفصول ليست محتوى إنتاجياً، وصفحات المانجا فنية مولّدة للعرض.
- **الشعار** أُعيد بناؤه كـ SVG اعتماداً على الهوية البصرية، وليس نسخة طبق الأصل من ملف التصميم الأصلي.
- **Firebase Storage غير مستخدم**؛ لا توجد صور مرفوعة.
